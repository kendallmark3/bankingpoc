# Build This App in Claude Code — 1 Hour, Zero Manual Coding

This is the exact sequence of prompts used to create the entire Bank of Intent application from scratch using Claude Code. No code was written by hand. Every file — backend, frontend, database schema, migrations, tests, logo, and documentation — was generated by typing natural language into Claude Code.

**Total time:** ~60 minutes  
**Manual keystrokes:** ~40 prompts  
**Lines of code written by hand:** 0

---

## What You Need Before Starting

1. **Claude Code installed**
   ```bash
   npm install -g @anthropic/claude-code
   ```
   Or download the desktop app from [claude.ai/code](https://claude.ai/code).

2. **An Anthropic account** with Claude Code access

3. **Prerequisites on your machine** (Claude will tell you if something is missing):
   - Python 3.11+
   - Node.js 20+
   - PostgreSQL 15+ running locally

4. **A project folder**
   ```bash
   mkdir bankingpoc
   cd bankingpoc
   ```

5. **Open Claude Code in that folder**
   ```bash
   claude
   ```
   Or open the folder in VS Code and use the Claude Code extension.

## Phase 1 — Spec First (5 min)

Before writing a single prompt for code, create a plain-text specification file. This is the only thing you write yourself — and it's just English sentences.

Create a file called `intents/intent.md` in your project folder. Write what you want the system to do:

```
What it does:
- Users register and log in
- Users create a banking profile (name, address, SSN last 4)
- Users open bank accounts (Checking, Savings, Money Market)
- Balances are computed on the server only
- Users can request overdraft limit increases
- Users manage a stock watchlist (max 10 symbols)
- A live stock ticker runs in the header
- A stock tip of the day shows on the dashboard

Rules:
- Never compute balances on the frontend
- Never store full SSN, only last 4 digits
- Never expose external API keys to the client
- All inputs validated by Pydantic
- Passwords hashed with bcrypt
- JWT access tokens (15 min) + opaque refresh tokens (7 days)
- PostgreSQL, normalized to 3NF
- FastAPI backend, React frontend
```

That's it. Save the file. Now open Claude Code and never touch a code file again.

## Phase 2 — Project Bootstrap (5 min)

Type these prompts one at a time. Wait for Claude to finish each one before sending the next.

**Prompt 1 — Initialize project guidance:**
```
/init
```
Claude reads your codebase and creates `CLAUDE.md` — a file it uses in every future session to stay consistent with your project.

**Prompt 2 — Generate the README:**
```
read intent and create readme.md for entire system
```

**Prompt 3 — Tighten the spec:**
```
tighten intent and update to reflect best practices — add refresh token rotation, API versioning under /v1/, response envelope, pagination, bcrypt cost, CORS, rate limiting, Alembic migrations, testing standards
```
Claude rewrites `intent.md` with concrete, implementable constraints.

## Phase 4 — Build Everything (30 min)

This is the big one. One prompt builds the entire stack.

**Prompt 5 — Build and run the full app:**
```
run test optimize and run all way to browser
```

Claude will:
- Scaffold the FastAPI backend (`/routers`, `/models`, `/schemas`, `/services`, `/dependencies`, `/core`)
- Write all SQLAlchemy models (11 tables)
- Create Pydantic schemas for every request and response
- Write business logic services (auth, profile, accounts, stocks)
- Generate an Alembic migration for the full schema
- Create a React frontend with routing, auth context, Axios interceptor, and 10 pages
- Write pytest integration tests against a real PostgreSQL test database
- Run the migrations
- Run the tests
- Start both servers

**If Claude hits an error** — just tell it:
```
fix that and continue
```
or describe what you see:
```
getting ModuleNotFoundError for greenlet, fix and retry
```

Claude knows what it built and will fix it without you reading any code.

**Common errors Claude will self-fix or fix on your prompt:**
- Missing packages (`greenlet`, `psycopg2-binary`, `email-validator`) → it installs them
- bcrypt version conflict → it pins `bcrypt<4`
- Async event loop scope mismatch in pytest → it updates `pytest.ini`
- TypeScript import errors with `verbatimModuleSyntax` → it rewrites the imports
- Wrong directory from `npm create vite` → it moves files to the right place

## Phase 5 — UI Polish (10 min)

After the app is running, look at it in the browser. If anything looks wrong, just describe it.

**Prompt 6 — Fix layout and styling:**
```
my profile does not work css is crap whole app is sized too small fix must be able to read as full screen professional
```

Claude:
- Diagnoses the null crash on the Profile page
- Rewrites `index.css` so `html`, `body`, and `#root` fill 100% height
- Rebuilds `Layout.tsx` as a true full-screen sidebar layout (280px sidebar, 60px header, scrollable main)
- Redesigns the Profile page as a 2-column card layout with a graceful "no profile" state

You can keep prompting with what you see:
```
the sidebar active state should use gold not blue
```
```
the dashboard account cards need more contrast
```

## Tips for Getting the Best Results

**Be specific about what you want, vague about how:**
```
# Good — tells Claude what, not how
add an overdraft request form with income, employment status, and consent fields

# Unnecessary — Claude already knows the right approach
add an overdraft request form using React controlled components with a useState hook...
```

**When something breaks, describe the symptom:**
```
# Good
the profile page crashes when I visit it for the first time

# Also good
getting a TypeError: Cannot read properties of null in the browser console on /profile
```

**When you want to change direction, just say so:**
```
actually make the sidebar 320px wide and use a lighter shade of navy
```

**When Claude finishes a big task, confirm before moving on:**
```
looks good, now add...
```

**To add new features after the baseline, reference it:**
```
looking at baseline.md section 9, implement feature A — real stock API integration with Alpha Vantage
```

## Continuing Development After the First Session

Start a new Claude Code session in the same folder:

```bash
cd bankingpoc
claude
```

Claude reads `CLAUDE.md` and `intents/revisions/baseline.md` automatically and picks up exactly where you left off. To add a feature:

```
read baseline.md — implement the real stock API feature using Alpha Vantage, replace the mock in services/stock.py, add the API key to Settings, update the baseline when done
```

Every feature you add follows the same loop:
1. Describe what you want in plain English
2. Claude builds it
3. You look at the result in the browser
4. You describe any changes
5. Claude fixes them
6. Commit and push with a prompt

## The Mental Model

Claude Code is not an autocomplete tool. It is a full software engineer that:
- Reads your entire codebase before acting
- Understands context from previous prompts in the session
- Runs commands, installs packages, starts servers, and reads error output
- Asks clarifying questions only when genuinely ambiguous
- Remembers preferences across sessions via `CLAUDE.md` and memory files

Your job is **product owner and QA**: decide what to build, look at what was built, and describe what needs to change. Claude's job is everything else.
